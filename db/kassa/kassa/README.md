# Касса — учёт расходов

Веб-приложение для учёта денежных расходов по нескольким организациям.
Чёрно-сиреневая тема, адаптивное (десктоп: сайдбар + таблица, телефон: выдвижное меню + карточки).
Несколько человек могут вносить операции одновременно — обновления приходят всем через WebSocket.

Есть вход по телефону и паролю и две роли:
- **Администратор** — создаёт, переименовывает и удаляет организации, управляет пользователями (создание/удаление, роли), видит и редактирует всё
- **Пользователь** — вносит и удаляет операции в организациях, но не может управлять организациями или пользователями

Есть сброс пароля по SMS-коду (шлюз нужно подключить самостоятельно — см. `server/sms.js`).

У каждой организации теперь два раздела:
- **Касса** — наличные, с категориями и отдельным остатком по каждому сотруднику (кто сколько получил/потратил)
- **Банк** — поступления и расходы по банковскому счёту, с комментариями и графиком динамики остатка

## Структура

```
kassa/
├── db/
│   ├── schema.sql     — таблицы, индексы, триггер истории изменений
│   ├── seed.sql       — демо-организации, категории, реальные данные «Аланди»
│   └── migrate.js     — применяет schema.sql (и seed.sql с флагом --seed) к базе
├── server/
│   ├── db.js           — подключение к PostgreSQL
│   ├── index.js        — Express-сервер + WebSocket
│   ├── middleware/
│   │   └── errorHandler.js
│   └── routes/
│       ├── orgs.js         — организации, категории, остаток кассы
│       └── transactions.js — операции (создание/удаление/список)
├── public/
│   ├── index.html
│   ├── app.js          — фронтенд, работает с /api/*
│   └── styles.css
├── .env                 — переменные окружения (заполнить своими значениями)
├── docker-compose.yml
├── Dockerfile
└── package.json
```

## Запуск через Docker (проще всего)

```bash
docker compose up --build
```

Схема базы применится автоматически при первом запуске (через `docker-entrypoint-initdb.d`),
но пользователи создаются отдельно (см. ниже) — при Docker-запуске выполните после старта:
```bash
docker compose exec app node db/migrate.js --seed
```

Приложение будет доступно на **http://localhost:3001**

## Запуск без Docker

1. Установите PostgreSQL и создайте базу, указанную в `.env` (`DB_NAME`)
2. Задайте `JWT_SECRET` в `.env` (любая случайная строка — используется для подписи токенов входа)
3. `npm install`
4. `npm run migrate:seed` — применить схему + создать демо-пользователей и демо-данные
   (или `npm run migrate` — только схема, без данных)
5. `npm run dev` — запуск с автоперезагрузкой (или `npm start`)

## Вход в систему

После `migrate:seed` в консоли выведутся логины. По умолчанию:

| Роль | Имя | Телефон | Пароль |
|---|---|---|---|
| Администратор | Админ | `+7000000000` | `admin123` |
| Пользователь | Алма | `+7700000001` | `alma123` |
| Пользователь | Динара | `+7700000002` | `dinara123` |

**Обязательно смените эти пароли** перед реальным использованием — сейчас это просто
демо-учётки, чтобы было с чем сразу зайти. Администратор может создавать новых пользователей
и удалять существующих прямо в интерфейсе (кнопка «Пользователи» внизу сайдбара), включая смену
роли на «Администратор». Отдельной формы смены собственного пароля пока нет — воспользуйтесь
«Забыли пароль?» на экране входа, это работает для любого пользователя.

## Обновление существующей базы (без потери данных)

Если база уже была создана раньше — **пересоздавать её не нужно**. Новая версия схемы
добавляет колонку `account` (касса/банк) и два представления безопасно, через
`ADD COLUMN IF NOT EXISTS`. Просто выполните:

```bash
node db/migrate.js
```

(без флага `--seed` — иначе поверх ваших данных снова добавятся демо-записи). Вся
существующая история операций сохранится и автоматически станет считаться кассовыми
операциями (`account = 'cash'`).

## Подключение SMS для сброса пароля

По умолчанию код сброса пароля просто печатается в консоль сервера — этого достаточно для
тестирования. Чтобы реально отправлять SMS:

1. Зарегистрируйтесь у SMS-провайдера (например, Mobizon, SMSC.kz, Twilio)
2. Впишите `SMS_API_URL`, `SMS_API_KEY`, `SMS_SENDER` в `.env`
3. Откройте `server/sms.js` и приведите тело запроса в соответствие формату именно вашего
   провайдера — единого стандарта у SMS-API нет, у каждого свой контракт запроса
